# Architecture

AppDeck is one C++17 translation unit (`src/main.cpp`) that includes its implementation headers, plus a few pure C++ policy headers that the portable tests compile on their own.

| File | Responsibility |
|---|---|
| `mac.hpp` | The small public Objective-C runtime / AppKit ABI bridge (`send<>`, x86_64 `stret`, alignment constants). |
| `core.hpp`, `edge_policy.hpp`, `usage_policy.hpp`, `workspace_filter.hpp`, `project_sync.hpp`, `automation_sync.hpp` | Pure policies: adapters, config editing, geometry and scrolling, limit cadence, allow-lists, project and automation reconciliation. Unit-tested. |
| `main.cpp` | App registry, persistence, launch adapters, main window, menus, localization. |
| `edge_panel.hpp` | The side panel: list, scrolling, drag-to-reorder, animation, global hot keys. |
| `window_control.hpp`, `ax_api.hpp` | Reopen, focus, 2×2 grid and restore through Accessibility. |
| `process_args.hpp` | Recognizing copies by their `--user-data-dir` argument. |
| `workspace_base.hpp`, `workspace_actions.hpp` | Connecting the base Codex workspace, shared history links. |
| `group_sync.hpp`, `project_server_sync.hpp` | Group journal, file application and Codex's own project API. |
| `usage_parse.hpp`, `usage_probe.hpp`, `usage_limits.hpp`, `usage_views.hpp` | Account limits: reply parsing, state-free probes, scheduling and cache, views. |
| `edge_selftest.hpp` | Acceptance aid that replays side panel gestures in a sandbox. |


## Runtime

C++17, public Objective-C runtime bridge, AppKit views. No Electron, Qt, WebView, screen-capture pipeline, child-process window embedding, private WindowServer APIs, app-bundle patching, telemetry or network client. The managed Codex processes remain independent ordinary macOS applications.

`main.cpp` owns the app registry, schema-2 persistence, NSWorkspace launch adapter and main UI. All controls share one button system (`styledButton`): borderless layer-backed NSButton subclasses whose style name (`primary`, `prominent`, `secondary`, `danger`, `overlay`) lives in the view identifier, drawn as capsules, with hover through an always-active tracking area; only the dock subclass accepts the first mouse click. The visual tokens ("Graphite glass") sit next to it: `ink`/`muted`/`faint`/`dim` text colours, `fill(alpha)` glass surfaces, `liveColor`/`warnColor`/`dangerColor` for state and six identity colours for the profile badges; colour is used for nothing else. Pages share one content column (264 pt from the left, 32 pt from the right edge) and one header, body and footer grid. Implementation headers are included in its anonymous namespace, so the whole app is one translation unit with no Xcode project. `mac.hpp` declares the small public ABI bridge (including x86_64 NSRect stret handling) instead of relying on Objective-C++.

## Side panel

`edge_panel.hpp`: nonactivating NSPanel subclass, cannot become key/main; public floating level; joins Spaces and is fullscreen auxiliary. NSVisualEffectView HUD material supplies the behind-window blur; a dark shade view between the blur and the content keeps text contrast independent of what is behind the panel. The dock is ONE column of profile rows (icon with the profile's colour badge, name, status light, limit, ⌃⌥ number) in an NSScrollView (overlay scroller), followed by a toolbar. It lists the profiles of EVERY registered app (`dockProfiles()`): the order of the `profiles` array in state.plist, which is the user's order — the same list drives Control-Option-1…8, the menu-bar menu and, filtered per app, the cards of the main window. `deck::edgeRows` gives one visible row per profile, at most six, shrunk until the dock leaves 24 pt of the screen free; the rest scrolls (`edgeScrollRange`), and the scroll offset survives rebuilds while the dock stays open (opening starts at the top). The dock has no "new profile" row (profiles are created in the main window). Rows are `AppDeckEdgeRowButton`s: a press that moves less than 4 pt is a click; beyond that the row is lifted and follows the pointer inside the list, the other rows glide to `edgeShiftedSlot`, the list auto-scrolls near its edges (`edgeAutoScroll`) and the drop is applied after the event (`edgeDropped:` → `moveProfileInList`, save, rebuild). The row menu offers the same moves for keyboard/VoiceOver users. While a drag runs the dock is never rebuilt. A CAGradientLayer masks the list; an edge shades only while it cuts through a row (`edgeCut`), so the list is clean at rest at its top and end; its orientation is taken from Core Animation (`contentsAreFlipped`). Up to 0.8 the dock grouped profiles by app; the first 0.9 load adopts that order once (`profileOrder` flag), new profiles join their app's profiles and duplicates follow their source. Rows represent profile states, not captured window pixels. Main window orderOut + NSApplicationActivationPolicyAccessory hides the manager and Dock identity; returning restores regular activation policy.

Geometry is pure (`edge_policy.hpp`, covered by `edge_test`): `edgeBounds` floats the dock `edgeMargin` (12 pt) off the right border of the target screen's visibleFrame, vertically centred, never outside it (on a screen too narrow for the margin it returns to the border); all four corners are rounded. `edgeFrame` unfolds it: the window's width grows along a quintic smootherstep while its right side stays put, so the window never reaches onto a neighbouring display; content keeps full width and is pinned to the moving left side. Height follows the visible rows and is recomputed on rebuild; there is no pager.

A common-run-loop NSTimer runs only while animating, using monotonic process uptime. Hide reverses from current progress. Accessibility preferences reduce motion/transparency. An NSApplication display-parameters notification repositions the panel after display changes.

The persistent two-second status timer already present in 0.1 refreshes managed-process states. It does not capture screens or inspect account credentials. Global hotkeys use public Carbon RegisterEventHotKey / InstallEventHandler on kEventHotKeyPressed (0.2.0 listened to kEventHotKeyReleased by mistake): Control-Option-Space and Control-Option-1..8 (place N of the side panel order). Conflict or unavailable APIs leave the menu-bar controls available. Hotkey handlers ignore events while an AppDeck modal is open.

## Window management

`ax_api.hpp` (state-free, shared with the smoke test) and `window_control.hpp`: optional dynamically loaded ApplicationServices APIs. The trust query never passes an options dictionary without `kAXTrustedCheckOptionPrompt`: for a process that is not yet trusted HIServices reads that value unchecked, and an empty dictionary ends in `CFGetTypeID(NULL)` (SIGSEGV at 0x8). That crashed 0.2.0 on every focus of an already running window. The silent query uses `AXIsProcessTrusted()`; the prompting one passes an explicit `true`. `scripts/verify.sh` re-runs the query inside a standalone unsigned-identity bundle because a terminal that is already trusted hides the defect. Window matching uses stored PID + bundle path + process launch date, then AXMainWindow or AXStandardWindow. Accessibility calls have a bounded per-call timeout. Focus first sends the ordinary `aevt/rapp` (reopen) Apple event addressed to that pid — exactly what a Dock click does — so a process whose last window was closed with the red button creates its window again (activation alone shows nothing); then it removes minimization and raises the window when Accessibility permission exists, and activates. Verified live: window count 0 -> 1 without any Automation prompt; `NSAppleEventsUsageDescription` is declared in case a future macOS asks.

The grid takes the first four running profiles in side panel order and the target screen's visibleFrame. Coordinates are converted from Cocoa bottom-left to Accessibility top-left using the primary display top edge. Actual resulting position/size is compared with the target. Fullscreen windows are skipped. Minimum-size constraints are reported, not bypassed.

The previous rectangles and retained AX window references are memory-only. Restore revalidates the exact profile launch identity, so a reused PID cannot restore an unrelated process. There is no forced always-on-top for foreign windows and no focus-fighting loop.

## Base profile and additional copies

An application group optionally owns a canonical `baseSource`. AppDeck will not choose a source under its own profile directory. Settings still flow from the source to stopped copies. With shared history enabled, the base also participates in project and automation reconciliation: only its stopped Desktop project cache and supported automation definitions may be updated, with backups. Its config, authentication and unrelated Desktop state are not rewritten. A `master=true` profile attaches to a unique non-managed process of the selected bundle or normally launches the original app only when doing so cannot resolve to a managed copy. Multiple untracked processes are a deliberate ambiguity error.

`process_args.hpp` reads a process's argument list through public `sysctl(KERN_PROCARGS2)` (what `ps` shows for the user's own processes; the environment block is not read) and extracts only AppDeck's own `--user-data-dir` marker. It gives every copy a durable identity: a copy that outlived a manager session or restarted itself is re-adopted (startup, every status tick, and right before a launch, so a twin is never started), and a process carrying a marker inside AppDeck's data root is never a master candidate. When no master candidate exists while copies are alive, the original is started with NSWorkspaceLaunchNewInstance and an empty configuration — default identity, no profile environment — and the result is rejected if it turns out to be a copy.

An unused card may be converted to master; otherwise a new card is added. No initialized account is overwritten. The master is launched first by “Launch all”. Duplicate of a master creates an independent linked profile rather than a second master.

For stopped linked copies, settingsSource is the external base (or the original AppDeck shared directory when no base is connected):

- config.toml copied through the conservative auth-store editor; previous local content backed up. Organization restrictions are not removed.
- AGENTS.md copied; previous local content backed up.
- skills/rules symlinked to the known selected base. Only AppDeck’s own former shared links can be repointed automatically; ordinary folders and unknown links cause a refusal.
- source MCP/provider configuration, including embedded keys, is explicitly shared with consent. This is not credential redaction of arbitrary TOML.
- additional instance uses separate CODEX_HOME, Electron user data, and CLI `file` credential store; common credential override environment variables are removed.

No auth.json, SQLite database, cookies, history files, entire user-data directory or entire CODEX_HOME is copied. Launch identity isolation is adapter-dependent.

## Claude Desktop adapter

`deck::Adapter::Claude` (bundle `com.anthropic.claudefordesktop`). Claude Desktop itself reads `CLAUDE_USER_DATA_DIR` and moves its Electron `userData` and logs there, so a copy gets that variable plus the usual `--user-data-dir=` argument (which is also the marker `process_args.hpp` recognises copies by). `CLAUDE_CONFIG_DIR` is deliberately NOT set: the Code tab keeps using `~/.claude`, i.e. settings and history stay shared while the desktop sign-in is per profile. The scrubbed launch environment also drops `ANTHROPIC_API_KEY`, `ANTHROPIC_AUTH_TOKEN`, `CLAUDE_CODE_OAUTH_TOKEN` and an inherited `CLAUDE_USER_DATA_DIR`. A generic master card (non-Codex apps) attaches to or normally starts the original app. Master cards follow their original automatically: when exactly one running process of the bundle is not a copy, the status tick adopts it (status only — nothing is raised or launched); two or more such processes stay ambiguous until an explicit click. Shared history, project synchronization and automation sharing remain Codex-only; Claude limits use the separate meter adapter below.

## Shared history (opt-in per group)

Codex keeps the thread list, projects, sections and pins in `state_N.sqlite` and thread content in `thread_history_N.sqlite` plus rollout files under `sessions/`; `threads.rollout_path` is absolute. A copy with its own CODEX_HOME therefore starts with an empty history even when its project list was seeded.

After explicit consent (`sharedHistory` on the app group; asked once at the first launch of a linked copy, in the connect dialog, or on the settings page) a linked copy is launched with `CODEX_SQLITE_HOME=<base>`. This is Codex's own switch: the core opens all of its databases there, and the Desktop layer checks the same variable and skips its direct maintenance of `<CODEX_HOME>/state_5.sqlite`. Nothing is cloned or symlinked at database level. Several Codex processes on one SQLite home is the product's normal configuration (CLI, IDE extension and Desktop share `~/.codex`).

`sessions`, `archived_sessions` and `thread-writer-locks` (allowlist `deck::historyLeaf`) are additionally linked from the copy's CODEX_HOME to the base, only when the copy has no non-empty folder of its own; existing local history is never hidden or removed. The links keep rollouts in one place, let Codex's "rollout must be inside sessions/" archive check pass, and share the writer-lock directory. Turning the option off removes only links that point at the connected base. The inherited environment is scrubbed of `CODEX_SQLITE_HOME` for every launch, so a non-sharing profile can never pick it up by accident.

Consequences that the UI states: history is genuinely shared in both directions together with the other databases in that folder (log, queue, memories, goals); resuming a thread under another account is governed by Codex/OpenAI; credentials, cookies and Electron user data stay per account. Verified with ChatGPT.app 26.908 against a synthetic base (the copy's core held `<base>/state_5.sqlite` open and created no databases of its own); not verified with real, different logged-in accounts.

## Group project synchronization

The installed Codex Desktop maintains two project stores. Its sidebar reads `local-projects` in each profile's `.codex-global-state.json`, ordered by `project-order`; its app-server owns native project records and thread memberships in the shared database. Desktop UI edits update both. Startup imports unmapped legacy entries into app-server, but does not replace the Desktop registry from `project/list`. Consequently neither copying JSON alone nor sharing the database is sufficient.

`group_sync.hpp` coordinates `project_sync.hpp`, `automation_sync.hpp` and `project_server_sync.hpp`. With a connected base and `sharedHistory` enabled, `Shared/<group-id>/group-sync-v1.json` is AppDeck's durable reconciliation journal. It holds canonical project records, revisions, deletion tombstones, each participant's observed/applied snapshots and native-apply acknowledgements. The base is a participant, not the authoritative winner. Initial registration unions existing valid local projects because absence in an unobserved profile cannot prove a past deletion. Subsequent additions, edits and removals are derived from changes since that participant's observed snapshot. Missing/unreadable files and unknown schemas are not empty snapshots.

Project conflicts use recorded revisions and a stable participant tie-break, never file modification time. Deletion wins over an edit of the same observed generation. Tombstones reject stale resurrection; restoration requires observing the deleted generation before an explicit re-add. Conflicts are recorded. The shared project list in AppDeck is a projection of this journal; its add/remove actions contribute observations through the same engine. Removing a project preserves its directory and tasks.

AppDeck's periodic group pass only captures observations and pending changes in its own journal; it does not write profile files or start a native helper from the UI timer. Application occurs on manual synchronization, before a full launch and during explicit project/owner actions, and is limited to fully stopped participants, including the base. Running instances retain their live cache and receive a pending marker. Focusing or reopening a window of an existing process is not a restart. `launch()` waits for successful reconciliation before starting a stopped process; graceful Restart terminates the exact process and only then follows that launch path. A profile or file changed during a native exchange causes the cache commit to be deferred.

`project_server_sync.hpp` uses the registered bundle's `codex app-server` with explicit `CODEX_HOME` and shared `CODEX_SQLITE_HOME`, a 30-second RPC deadline and bounded responses. It lists native projects, imports using the stable legacy project ID as idempotency key, updates desired names/roots and deletes only explicitly tombstoned identities with native mappings collected from the group. Unresolved tombstone mappings prevent a successful apply. Before deletion it enumerates active and archived member IDs, then clears membership through `thread/metadata/update` with `projectId:""`; it does not request thread contents or run a model turn. An import retry can recover an earlier successful mapping and then apply newer desired content. A mapped native project that disappeared unexpectedly fails closed rather than being recreated silently.

After native success, the stopped profile's allowlisted cache is projected: local registry/order and legacy path labels, its host-scoped legacy/native ID mapping, and selected/pinned/projectless membership fields needed to remove deleted projects. Account-bound `cloud:` entries and unrelated window/account state are preserved; project data is shape-checked and size-bounded. The previous file is retained as `.appdeck-previous`, unchanged files are not rewritten, and each completed participant is acknowledged durably. Partial failure leaves a retryable journal; this is not a cross-file database transaction. AppDeck never copies, symlinks or edits a Codex database directly.

The older `workspace_filter.hpp` allowlist remains the initial-seed adapter when shared history is off. Historical behavior in 0.5–0.7.2 was a base-to-copy union before launch, with no base writes or deletion propagation; group synchronization supersedes that behavior in 0.8.0. The Foundation JSON loader is bounded to 8 MiB and rejects symlink files; group observations are checked against the supported registry schema. Settings (`config.toml`, `AGENTS.md`, skills/rules) continue to use their existing base-to-copy path independently of group project reconciliation.

## Automation definitions and execution ownership

Codex definitions are separate `automations/<id>/automation.toml` files. `automation_sync.hpp` parses only supported bounded forms, preserving definition text and checking identity/schema before synchronization. The group journal stores one canonical definition, one execution owner, per-profile observations and unresolved conflicts. Body/schedule edits from any supported replica can update the definition. Deletion of an already observed definition creates a tombstone; absence during bootstrap does not. Concurrent differing edits and delete-versus-edit conflicts remain unresolved without overwriting those variants.

A newly observed definition initially belongs to its creator. Only the owner receives its canonical ACTIVE/PAUSED execution status; replicas are projected PAUSED. Setting a replica ACTIVE does not elect another owner: it is recorded as unsafe and a stopped replica is paused during application. Only the owner's pause/resume change controls the group status. Owner reassignment is explicit in Settings, requires the participating Desktops to be stopped, pauses other copies before activating the new owner, and preserves a globally paused definition. Removing or unlinking an owning profile is blocked until ownership is reassigned. Disabling sharing for a group with automation definitions also requires its Desktops to be stopped.

Only supported definition files are transferred, with previous files retained as `.appdeck-previous`; no full automation directory, database, queue, run history or memory is copied. A duplicate active definition or unreadable peer prevents safe activation. The selected Codex profile must be running for its own scheduler to execute an active definition; AppDeck does not provide scheduling or automatic owner failover. Runtime/editor behavior under different real accounts and an actual scheduled firing remain acceptance boundaries.

Synchronization engines and file application are tested against isolated fixtures; project import/update/delete and shared `CODEX_SQLITE_HOME` identity are also exercised with the installed native app-server. Membership pagination and clearing have a separate offline protocol fixture, not a completed live-account execution test. See [SYNC_DESIGN.md](SYNC_DESIGN.md) for the conflict and ownership rules and [TESTING.md](TESTING.md) for the verification status.

## Account limits (opt-in per group)

`usage_limits.hpp` asks Codex itself. For one profile at a time a worker thread (NSThread) starts the registered bundle's own `Contents/Resources/codex app-server` through NSTask with a scrubbed environment and the profile's `CODEX_HOME`, and speaks the documented newline-delimited JSON-RPC over stdio: `initialize`, `initialized`, `account/read {refreshToken:false}`, `account/rateLimits/read {excludeResetCreditDetails:true}` — the protocol's own settings for a background poll. Reading uses `poll`/`read` with a 20 s deadline; the write end has `F_SETNOSIGPIPE`, so a probe that dies early cannot kill AppDeck. Closing stdin makes app-server exit; it is terminated if it lingers. The worker touches no AppDeck state and hands an immutable result to the main thread (`performSelectorOnMainThread`). AppDeck never opens auth.json, holds no token and still has no network client.

The probe is an ordinary second Codex client of that profile: same `CODEX_HOME` and the same database folder its window uses (`CODEX_SQLITE_HOME=<base>` only when history is shared). An "isolated" empty SQLite home was tried and rejected: a fresh state database makes Codex re-index every rollout under `CODEX_HOME`, and startup times out.

Claude profiles use the same scheduler, cache and views through a second probe. Claude Desktop passes its sign-in to the embedded Claude Code in memory (host-managed credentials), so there is nothing on disk to ask with; the standalone CLI may not be signed in at all. AppDeck therefore keeps one Claude Code configuration folder per profile (`ClaudeMeter/<id>` in its own data root, never `~/.claude`) that the user signs in once with the CLI's own `claude auth login --claudeai`, started in Terminal from a generated 0700 script. A probe runs `claude auth status`, then `claude -p --safe-mode --input-format stream-json --output-format stream-json --verbose --no-session-persistence` and writes a single `control_request` `{subtype:"get_usage", skip_behaviors:true}` — the request Claude Code's own schema describes for usage meters. `--safe-mode` disables hooks, plugins, MCP servers and CLAUDE.md while authentication works normally; no user message is sent, so there is no model turn. The environment is scrubbed of `ANTHROPIC_*`, `CLAUDE_CODE_*`, `CLAUDECODE*` and a foreign `CLAUDE_CONFIG_DIR`; only the narrow `DISABLE_AUTOUPDATER`, `DISABLE_ERROR_REPORTING` and `DISABLE_TELEMETRY` are set — `CLAUDE_CODE_DISABLE_NONESSENTIAL_TRAFFIC` makes Claude Code skip the usage request itself and answer `rate_limits:null` (the 0.7.0 defect). Windows come from the server's `rate_limits.limits[]` list (`kind` session / weekly_all / weekly_scoped with `scope.model.display_name`, `percent`, `resets_at`), which mirrors Claude's own usage screen and does not depend on client-side feature flags (`model_scoped` vanishes with telemetry off); `seven_day` / `five_hour` / `model_scoped` / legacy `seven_day_opus|sonnet` are the fallback. Order: weekly all models, 5 hours, per-model; the dock's single number is the window closest to its wall and the bar has one segment per window.

`usage_probe.hpp` holds both probes as state-free functions (`usageProbeCodex`, `usageProbeClaude`), so `tests/macos_api_smoke.cpp --claude-probe` executes the production exchange against a signed-out scratch folder. `usage_parse.hpp` (shared with the smoke test) normalises replies into `{windows:[{used,minutes,resets}], plan, reached}` and `{signedIn,kind,email,plan}`. Every field is type-checked; a non-object payload yields "no windows", never an exception. Windows are classified by duration (`usage_policy.hpp`), not by the `primary`/`secondary` name: a Pro account reports the weekly window as `primary` and has no 5-hour window. Cadence is pure policy, covered by `usage_test` (see below).

Cadence since 0.7.2 is one rule (`usage_policy.hpp`, simulated for a whole day in `usage_test`): an account at most once per hour whatever the state of its profile, and automatic probes of any two profiles at least five minutes apart (`usageLastProbe`, set only when a helper process is really started); there are no event-driven automatic probes (launch, stop, window reset and sign-in wait probes were removed in 0.7.2). A manual refresh is immediate with a 20 s floor per account. A window whose reset time has passed is drawn grey until the next probe. Only display data is cached on the profile (`usage`): percentages, reset times, plan, reached-type and the account e-mail as a label; it is sanitised on load, removed when the feature is switched off and never exported by diagnostics. On failure the last good numbers stay visible, marked stale, unless the account itself is gone (`auth`, `apikey`). `usage_views.hpp` creates the card strip and dock indicators once and updates them in place, so an answer never rebuilds the window or resets a scroll position.

`mac.hpp` carries per-architecture `alignRight`/`alignCenter`: AppKit's NSTextAlignment uses the iOS numbering everywhere except x86_64 macOS (0.2/0.3 hard-coded 1 for "centre", which is "right" on Intel).

## Localization

The interface is English or Russian. Every visible string is written in place as `T("English", "Русский")`, next to its use, so the two languages cannot drift apart. The language is decided once at launch from `NSBundle.preferredLocalizations`: the bundle declares `CFBundleLocalizations` en/ru and ships `en.lproj` / `ru.lproj` (Info.plist strings), so AppDeck and AppKit's own panels choose the same language — Russian when the user prefers Russian over English (or picks it for AppDeck in System Settings), English otherwise. Dates in limit captions use the matching locale. `tools/check_i18n.py` (part of `make test`) fails on Cyrillic outside a `T()` pair and on differing printf conversions between the halves. The documentation and the bundled user guide (`Help.html`, rendered from `docs/USER_GUIDE.md`) are English.

## Lifecycle actions

A running card offers Close, Restart and Window; a stopped one Launch and Folder (the row is rebuilt when the running state flips). Both Close and Restart send the ordinary `terminate` request after a confirmation; Restart records the profile with a 25 s deadline and `restartPump()` (status tick) launches it again only once `running()` is really gone — no kill, no race with Electron's shutdown. A stop requested through AppDeck disarms the 8 s launch watchdog, so it is never reported as a failed start. The dock rows carry the same actions in a context menu.

## Persistence / distribution

Existing state schema 1 is backed up once to `state-v1.before-0.2.plist` before schema-2 writes. AppDeck 0.1 refuses schema 2. Later versions retain schema 2 with optional group/profile keys. Version 0.8 additionally keeps the versioned synchronization journal under the group's Shared directory; it is independent of Codex database schemas.

`APPDECK_DATA_ROOT` (absolute path) runs a completely separate manager — own state, profiles and singleton lock — for acceptance runs that must not touch real data. `APPDECK_RENDER_DIR` draws every page and the side panel into PNG files through `cacheDisplayInRect:` and exits; in that mode nothing is saved, locked, launched or registered, modal helpers return immediately, and no Screen Recording permission is involved. `APPDECK_DOCK_SELFTEST=1` (only together with `APPDECK_DATA_ROOT`) replays side panel gestures through the app's own event queue and exits (see [TESTING.md](TESTING.md)). Profile directories remain unchanged. Root/profile permissions 0700, generated settings 0600, singleton advisory lock. No forced killing of managed applications on exit.

Builds use the system clang, AppKit and Apple `codesign` (`scripts/build.sh`); `tools/verify_bundle.py` additionally checks both slices statically (PIE, minimum macOS, only system imports, complete code directories). Ad-hoc signing is not a publisher identity: Developer ID signing and notarization remain release requirements.

Native-deletion recovery: before an explicit apply/launch, at least one stopped participant validates the shared native registry even when its cache revision is unchanged. A successful complete `project/list` with absent known native IDs returns `missingLegacyIds` before mutations. The group records these confirmed deletions as a `codex-server` observation, persists tombstones and retries the pass (bounded to three attempts). This handles stale Desktop caches without resurrecting deleted native IDs.
